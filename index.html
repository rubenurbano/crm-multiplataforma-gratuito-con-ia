01

Conceptos fundamentales

Antes de tocar una sola línea de código o panel de configuración, necesitas entender los cimientos. Esta sección responde a las preguntas qué, para qué y por qué de cada decisión técnica del proyecto.

¿Qué es un CRM Single-Tenant?

Un CRM (Customer Relationship Management) es un sistema centralizado para gestionar las interacciones con los clientes: contactos, conversaciones, oportunidades de venta y tareas de seguimiento.

Un CRM single-tenant (de empresa única) es una instalación dedicada a una sola organización. Al acceder al sistema no existe un selector de empresas ni un creador de negocios: el usuario ingresa directamente a su tablero de control, sus contactos y sus canales de comunicación.

🔒 Privacidad y aislamiento

Cada empresa posee su propia base de datos aislada, evitando mezclar información sensible entre diferentes clientes.

⚡ Simplicidad operativa

Elimina las capas complejas de abstracción multi-inquilino (multi-tenant), lo que reduce errores de enrutamiento y simplifica la interfaz.

🤖 Multi-asistente

Aunque pertenece a un solo negocio, permite crear múltiples asistentes virtuales departamentales que comparten la misma base de contactos unificada.

¿Por qué la API oficial de Meta previene la suspensión de números?

Existen dos caminos para automatizar mensajería en WhatsApp, y solo uno es seguro a largo plazo:

SoluciónCómo funcionaRiesgo
No oficial
Evolution APIBaileysCódigo QR		 Emulan el protocolo web de WhatsApp para hacerse pasar por un cliente humano. Alto. Meta detecta este comportamiento de forma automatizada y suspende permanentemente el número.
Oficial
WhatsApp Cloud API		 Infraestructura autorizada por Meta, diseñada para uso empresarial a escala. Nulo por uso no autorizado. Garantiza estabilidad, entregas y soporte para plantillas aprobadas.

🚨 Regla de oro

Si el objetivo es un sistema duradero, solo la API Oficial de Meta es aceptable. Las soluciones no oficiales pueden parecer cómodas al principio, pero el riesgo de perder el número es total e irreversible.

Propiedad de un algoritmo que garantiza que ejecutar la misma operación múltiples veces produzca el mismo resultado sin duplicaciones.

El sistema recopila automáticamente los identificadores críticos y los almacena de forma segura:

Tablero Kanban omnicanal

El CRM ofrece una interfaz moderna para la gestión de clientes:

  • Registro único de contacto: cuando un cliente escribe por WhatsApp o Instagram, el sistema verifica sus identificadores. Si ya existe, la conversación se asocia a su ficha única, evitando duplicados.
  • Vista Kanban: oportunidades organizadas por etapas (Contacto Inicial, Presupuesto Enviado, Negociación, Ganada, Perdida).
  • Filtros y búsqueda: por nombre, teléfono, etiqueta o canal, con exportación a CSV.

Creación de múltiples asistentes departamentales

Para cada asistente se configura:

  • Nombre y avatar: identidad visual y pública del bot.
  • Canal asignado: número de WhatsApp o cuenta de Instagram específica.
  • Objetivo y tono: instrucciones de personalidad (Ejecutivo, Cercano, Técnico).
  • Horario de atención: franja en la que el bot responde automáticamente.
  • Reglas de transferencia: condiciones para derivar a un operador humano.
  • Estado de publicación: control de versiones entre borrador y publicado.

Base de conocimiento

Cada asistente puede alimentarse de documentos institucionales:

  • Formatos admitidos: PDF con texto extraíble, TXT, CSV, XLSX sin macros e importación web segura.
  • Seguridad: el contenido cargado se procesa como información de consulta y nunca como instrucciones del sistema, protegiendo al bot contra suplantación.

Asistente Privado del Propietario

Es un bot de control interno exclusivo para la dirección de la empresa:

  • Autenticación estricta: solo responde a mensajes del número internacional autorizado del dueño.
  • Órdenes en lenguaje natural: "¿Cuántas ventas cerramos hoy?", "Pausá el asistente de soporte", "Agendá una reunión con Juan mañana".

Los comandos se ejecutan según niveles de riesgo:

Fases 7 y 8 — Control humano, pruebas, seguridad y despliegue

Módulo de intervención humana

Cuando un operador toma el control de un chat desde el CRM:

  1. La respuesta automática de la IA se desactiva inmediatamente para ese contacto.
  2. Se cancelan las tareas en segundo plano pendientes.
  3. Se registra el evento en ActivityLog indicando qué agente tomó el control.
  4. Para devolver el control a la IA, el operador hace clic explícitamente en "Devolver a IA".

Modo Seguro y simulación

Un estado de simulación ideal para desarrollo y pruebas:

  • Permite probar la lógica del CRM, el enrutamiento de bots y la creación de oportunidades.
  • Bloquea las llamadas salientes reales a Meta: ningún mensaje real se envía al cliente.
  • Registra las interacciones bajo el estado SIMULATED.

Webhooks serverless, validación HMAC e idempotencia

  1. Validación de firma HMAC (SHA-256)

    Cada petición de Meta incluye un encabezado de firma. El servidor calcula el hash con el App Secret y rechaza cualquier petición inválida.

  2. Respuesta rápida (< 3 segundos)

    El webhook valida, guarda el evento y responde 200 OK inmediatamente a Meta, delegando el procesamiento pesado a una Netlify Background Function.

  3. Idempotencia

    El servidor comprueba si el identificador del mensaje ya existe en ProcessedWebhookEvent. Si ya fue procesado, se descarta para evitar responder dos veces.

Pruebas y despliegue final

  1. Pruebas unitarias e integración

    Vitest y Playwright sobre escenarios simulados.

  2. Verificación de tipado y lint

    Sin errores de compilación ni warnings críticos.

  3. Despliegue en Netlify

Casos prácticos integradores

Dos escenarios reales que combinan todo lo aprendido. Cada uno incluye el flujo completo desde que el cliente escribe hasta que el sistema responde.

Proyecto Integrador 1 — Captura, calificación y cierre de ventas por WhatsApp

Escenario: un cliente potencial envía el mensaje "Hola, quiero información sobre sus servicios" al WhatsApp oficial de la empresa.

  1. Recepción

    Meta envía la notificación del mensaje al Webhook de la app en Netlify.

  2. Autenticación e idempotencia

    El servidor valida la firma HMAC SHA-256 y verifica que el ID de mensaje no haya sido procesado.

  3. Gestión del contacto

    El sistema busca el número telefónico en la tabla Contact. Si no existe, crea un nuevo registro y le asigna la etapa Contacto Inicial.

  4. Respuesta automática de la IA

    El asistente de Ventas analiza la consulta, consulta la base de conocimiento y responde con los planes disponibles.

  5. Detección de intención y actualización

    Cuando el cliente responde "Me interesa el Plan Pro, quiero contratarlo", el bot ejecuta la herramienta change_opportunity_stage, mueve la oportunidad a Negociación y notifica al equipo comercial.

Resultado esperado

El CRM registra la oportunidad en la columna correcta del Kanban, crea una notificación interna y, si procede, una tarea de seguimiento asignada a un comercial humano.

Proyecto Integrador 2 — Control directivo por mando interno de WhatsApp

Escenario: el dueño de la empresa envía el mensaje "Muéstrame el resumen de ventas de hoy" desde su teléfono personal autorizado.

  1. Validación del remitente

    El sistema verifica que el número pertenezca a la lista de propietarios en CompanySettings.

  2. Procesamiento de la orden

    El Asistente del Propietario interpreta la solicitud y ejecuta la herramienta get_daily_summary.

  3. Respuesta ejecutiva

    El bot responde por WhatsApp con el resumen formateado.

Ejemplo de respuesta del bot

"Hoy se registraron 12 nuevos contactos, 4 oportunidades pasaron a Negociación y se cerraron 2 ventas por un total de $1,500 USD."

Ejercicios de práctica guiada

Ejercicio 1 — Mapear la conversación al CRM

Objetivo: entender cómo los mensajes entrantes se convierten en registros del CRM.

Enunciado: un cliente nuevo envía tres mensajes en WhatsApp en los que primero saluda, luego pregunta el precio y finalmente pide una cita. ¿Qué registros se crean en la base de datos?

Solución esperada:

  1. Se crea un registro en Contact con el número de teléfono y el nombre (si lo proporciona).
  2. Se crea un registro en Conversation vinculado al contacto.
  3. Se crean tres registros en Message, uno por cada mensaje recibido.
  4. Se crea una Opportunity en etapa Contacto Inicial.
  5. Cuando el cliente pide la cita, el bot ejecuta create_booking y se registra la cita.
Ejercicio 2 — Detección de idempotencia

Objetivo: reconocer cuándo un evento es un duplicado.

Enunciado: Meta envía dos veces el mismo evento (mismo ID de mensaje) con 500 ms de diferencia. ¿Qué debe hacer el sistema?

Solución esperada: la primera petición se procesa y registra en ProcessedWebhookEvent. La segunda se detecta como duplicada por el ID y se descarta sin procesar, evitando que el cliente reciba dos respuestas.

Ejercicio 3 — Clasificar el nivel de riesgo

Objetivo: diferenciar los cuatro niveles de riesgo del Asistente Privado del Propietario.

Enunciado: clasifica las siguientes órdenes:

  1. "¿Cuántos contactos nuevos tengo?"
  2. "Creá una tarea para llamar a Juan mañana."
  3. "Enviá un mensaje masivo a todos los clientes con la nueva promoción."
  4. "Eliminá todos los contactos inactivos de los últimos 2 años."

Solución esperada:

  • (1) Nivel 1 — Lectura: ejecución inmediata.
  • (2) Nivel 2 — Escritura reversible: se ejecuta y confirma.
  • (3) Nivel 3 — Acción sensible: requiere confirmación explícita por chat.
  • (4) Nivel 4 — Acción destructiva: doble confirmación o derivación al panel web.
Ejercicio 4 — Validar una firma HMAC

Objetivo: comprender el mecanismo de autenticación de webhooks.

Enunciado: ¿qué pasos ejecuta el servidor cuando recibe una petición de Meta?

Solución esperada:

  1. Lee el cuerpo crudo de la petición y el encabezado de firma.
  2. Calcula el HMAC SHA-256 del cuerpo usando el App Secret.
  3. Compara el hash calculado con la firma recibida.
  4. Si coinciden, procesa el evento; si no, rechaza con código 401.

33 preguntas y respuestas por niveles

Las 33 dudas más frecuentes del proyecto, ordenadas en tres niveles de dificultad. Pulsa sobre cada pregunta para desplegar la respuesta.

Nivel Básico

Preguntas 1 a 11

1. ¿Qué es un CRM Single-Tenant y cuál es su principal ventaja?

Es una aplicación diseñada exclusivamente para una sola empresa. Su principal ventaja es que elimina capas innecesarias de selección de negocios, permitiendo acceder directamente a los datos, clientes y canales de la compañía con máxima seguridad.

2. ¿Por qué se debe usar la API Oficial de WhatsApp Cloud en lugar de escanear un código QR con herramientas no oficiales?

Porque las herramientas no oficiales no cuentan con el respaldo de Meta y provocan la suspensión o bloqueo permanente del número de teléfono. La API Oficial garantiza estabilidad y cumplimiento de políticas.

3. ¿Por qué es obligatorio comprar una tarjeta SIM nueva para la automatización?

Para separar completamente la comunicación personal de la empresarial y evitar el riesgo de perder la cuenta personal de WhatsApp en caso de cometer errores durante las pruebas iniciales.

4. ¿Qué función cumple OpenCode en este proyecto?

OpenCode actúa como un agente de desarrollo asistido por IA que interpreta el prompt maestro y se encarga de programar, auditar y configurar la aplicación de forma autónoma en el navegador.

5. ¿Qué proveedores de inteligencia artificial y modelos se utilizan para mantener la app 100% gratuita?

Se utiliza OpenRouter como plataforma agregadora, conectando modelos gratuitos de alto rendimiento como DeepSeek V3 o DeepSeek Flash.

6. ¿Dónde se alojan la aplicación web y la base de datos sin pagar suscripciones?

La aplicación web se despliega en Netlify (plan serverless gratuito) y la base de datos PostgreSQL se aloja en Supabase (plan cloud gratuito).

7. ¿Qué redes sociales se pueden conectar al CRM en este tutorial?

Se integran las API oficiales de WhatsApp Cloud API e Instagram Messaging API.

8. ¿Se pueden tener múltiples asistentes virtuales en una misma empresa?

Sí. Aunque el sistema es para una sola empresa, se pueden crear múltiples asistentes virtuales departamentales (Ventas, Cobros, Soporte, Reservas, Administración) compartiendo la misma base de datos de clientes.

9. ¿Qué sucede cuando un operador humano interviene en una conversación desde el CRM?

La inteligencia artificial se pausa automáticamente en esa charla, se cancelan los procesos automáticos pendientes y el agente humano toma el control manual del chat.

10. ¿En qué formatos se pueden subir documentos a la base de conocimiento de la IA?

Se pueden subir archivos PDF con texto extraíble, archivos TXT, hojas CSV, tablas XLSX sin macros, listas de Preguntas Frecuentes (FAQ) o importar contenido desde páginas web.

11. ¿Qué es el Asistente Privado del Propietario?

Es un bot de control interno que solo responde a los números de WhatsApp autorizados del dueño de la empresa para ejecutar órdenes administrativas mediante comandos de texto o voz.

Nivel Avanzado

Preguntas 12 a 22

12. ¿Cuáles son los puntos principales que evalúa el cuestionario de auditoría en la Fase 0?

Inspecciona el estado real de la empresa en Meta: existencia de la Página de Facebook, Portafolio Comercial, App de Desarrollador, Cuenta de WhatsApp Business API, número registrado, cuenta profesional de Instagram e identificadores clave.

13. ¿Qué credenciales genera Meta y cómo se almacenan en la aplicación?

Genera el App ID, App Secret, WhatsApp Business Account ID, Phone Number ID, Verify Token y Token de Acceso Permanente. Se almacenan cifrados con AES-256 en la base de datos y en el archivo de variables locales.

14. ¿Cómo evita el CRM la duplicación de contactos entre WhatsApp e Instagram?

El sistema unifica a los clientes bajo una ficha única en la tabla Contact, asociando los identificadores externos de cada canal sin duplicar perfiles.

15. ¿Para qué sirve el archivo local configuracion-y-credenciales.txt?

Es un documento local y confidencial donde se recopilan los parámetros del negocio, reglas de automatización, claves de API y cadenas de conexión antes de la compilación.

16. ¿Cuáles son las tablas principales del modelo de datos en PostgreSQL con Prisma?

CompanySettings, User, Role, Assistant, ChannelConnection, Contact, Conversation, Message, Opportunity, CrmTask, KnowledgeSource, ToolPermission, ProcessedWebhookEvent y UsageRecord.

17. ¿Qué parámetros se configuran al crear un asistente departamental?

Nombre, avatar, objetivo, canal asignado, tono de comunicación, instrucciones personalizadas, prohibiciones, horario de atención, mensaje de bienvenida, conocimiento activo y herramientas permitidas.

18. ¿Qué restricciones aplican a los archivos subidos en la base de conocimiento?

Los PDF deben contener texto seleccionable (no solo imágenes escaneadas sin OCR), los XLSX no deben incluir macros y los archivos se tratan como datos de consulta y no como instrucciones del sistema.

19. ¿Cómo se protegen los tokens y claves secretas guardadas en la base de datos?

Se encriptan utilizando algoritmos de cifrado simétrico AES-256 y se muestran enmascarados en la interfaz del usuario.

20. ¿Qué hace el "Modo Seguro" durante las pruebas de la aplicación?

Simula la lógica del CRM y las respuestas de la IA guardando registros como SIMULATED, bloqueando cualquier envío real de mensajes a través de las API externas de Meta.

21. ¿Qué requisitos exige Meta Developers para publicar la aplicación web?

Configurar el dominio de la app en Netlify, publicar la URL de las Políticas de Privacidad y publicar la URL de los Términos de Servicio.

22. ¿Cómo solucionar un bucle de procesamiento infinito en OpenCode?

Si el agente trabaja por más de 30 minutos sin avanzar, se debe pausar manualmente la ejecución, consultar qué paso completó y suministrarle el dato o clave que está bloqueando la tarea.

Nivel PRO

Preguntas 23 a 33

23. ¿Cómo se construye el System Prompt dinámico antes de cada consulta al LLM?

Une los datos de la empresa, parámetros del asistente, canal activo, fuentes de conocimiento, historial de los últimos mensajes, estado del cliente en el CRM, fecha/hora local y herramientas validadas por Zod.

24. ¿Cómo se implementa la validación de herramientas internas con Zod?

Cada función ejecutable por la IA se define con esquemas Zod que verifican estrictamente los tipos de datos de entrada, el rol del usuario, los permisos del bot y la idempotencia.

25. ¿Cómo se clasifican los niveles de riesgo para las órdenes del Asistente Privado del Propietario?

1) Lectura (ejecución directa), 2) Escritura Reversible (ejecuta y confirma), 3) Acciones Sensibles (muestra resumen y exige confirmación en chat), y 4) Acciones Destructivas/Financieras (doble confirmación o derivación al panel).

26. ¿Cómo se garantiza la idempotencia al recibir Webhooks de Meta?

Cada evento entrante se registra en la tabla ProcessedWebhookEvent con su ID de mensaje único provisto por Meta. Si ingresa una petición duplicada, el servidor la descarta de inmediato.

27. ¿Qué medidas de seguridad evitan ataques de Prompt Injection en los bots?

Se trata todo mensaje de cliente como dato no confiable, se aplican delimitadores estrictos de contexto, se prohíbe la divulgación de prompts internos y se limita el acceso a herramientas según el rol.

28. ¿Cómo se logra que los Webhooks respondan a Meta en menos de 3 segundos?

El endpoint de la API recibe el mensaje, valida la firma HMAC, guarda el evento inicial y responde inmediatamente un estado HTTP 200 OK, delegando el procesamiento pesado a una Netlify Background Function.

29. ¿Cómo se efectúa la validación de firmas HMAC en los Webhooks entrantes?

Se calcula un hash HMAC-SHA256 del cuerpo de la petición utilizando el App Secret de la aplicación y se compara con el encabezado de firma. Si no coinciden, se rechaza la petición.

30. ¿Cómo solicitar y gestionar el Acceso Avanzado en Instagram Messaging API?

Se deja la integración totalmente preparada mediante escenarios de prueba, se documenta el permiso requerido de mensajería de Instagram y se envía la solicitud formal de revisión desde el panel de Meta Developers.

31. ¿Cómo se monitorea el consumo de tokens y costes de ejecución?

Cada interacción con el modelo de lenguaje en OpenRouter registra una entrada en la tabla UsageRecord, detallando el asistente utilizado, el conteo de tokens de entrada/salida y el coste estimado.

32. ¿Cómo se ejecutan pruebas automáticas sin realizar envíos reales?

Se utilizan Vitest y Playwright ejecutando pruebas unitarias e integraciones sobre escenarios simulados en Modo Seguro, validando rutas y esquemas sin consumir tokens ni enviar mensajes.

33. ¿Cuáles son los criterios estrictos de terminación del proyecto (Fase 8)?

Aplicación single-tenant funcional, múltiples asistentes, integración oficial con Meta en WhatsApp e Instagram, validación de firmas HMAC, comando interno del propietario restringido a números autorizados, pruebas automáticas aprobadas y archivo README.md completo.

Errores frecuentes explicados en detalle

🔁 Bucle de OpenCode sin terminar

Qué ves: el agente sigue generando código o reescribiendo archivos sin llegar al final.

Por qué ocurre: falta una credencial o un dato imprescindible que el agente no puede adivinar.

Cómo se soluciona:

  1. Detén la ejecución en OpenCode con el botón de pausa.
  2. Pregunta al agente: "¿Qué paso completaste y qué te falta?"
  3. Proporciona manualmente el dato o credencial que bloquea la tarea.
  4. Reanuda la ejecución.
🔐 Error 403 / Invalid Signature en el Webhook

Qué ves: Meta envía eventos, pero el servidor los rechaza con código 403.

Por qué ocurre: el App Secret o el Verify Token configurados en las variables de entorno no coinciden con los de Meta.

Cómo se soluciona:

  1. Entra en Meta Developers y copia de nuevo el App Secret.
  2. Pega el valor exacto en el archivo .env.local.
  3. Verifica que el Verify Token sea idéntico al configurado en el panel de Webhooks de Meta.
  4. Reinicia el servidor de desarrollo o redespliega en Netlify.
📭 Meta no entrega mensajes de prueba

Qué ves: el webhook está configurado, pero no llegan mensajes de prueba.

Por qué ocurre: el token temporal expiró, el número no está verificado o el webhook no está suscrito al evento correcto.

Cómo se soluciona:

  1. Genera un Token de Acceso Permanente desde Meta Business Suite.
  2. Confirma que el número recibió y validó el código SMS de verificación.
  3. Revisa que el webhook esté suscrito a los eventos de mensajes.
  4. Reenvía una prueba desde el panel de Meta Developers.
🗄️ Error de conexión con Supabase

Qué ves: la aplicación no puede conectarse a la base de datos.

Por qué ocurre: la URL de conexión es incorrecta, la contraseña cambió o la red bloquea el puerto.

Cómo se soluciona:

  1. Revisa la variable DATABASE_URL en Supabase → Settings → Database.
  2. Confirma que el puerto 5432 esté habilitado.
  3. Verifica que la contraseña no contenga caracteres que deban ser escapados en la URL.
  4. Ejecuta npx prisma db push para sincronizar el esquema.
🕵️ Prompt Injection detectada en producción

Qué ves: un usuario intenta que el bot revele instrucciones internas o ejecute acciones no permitidas.

Por qué ocurre: el mensaje del usuario contiene texto diseñado para cambiar el comportamiento del modelo.

Cómo se soluciona:

  1. Trata siempre los mensajes del cliente como datos no confiables.
  2. Aplica delimitadores explícitos alrededor del contexto del cliente.
  3. Bloquea la divulgación del System Prompt en la configuración del asistente.
  4. Limita las herramientas disponibles según el rol del usuario.
⚏ Webhook tarda más de 3 segundos en responder

Qué ves: Meta reintenta eventos porque el webhook no responde a tiempo.

Por qué ocurre: el procesamiento pesado se está ejecutando en el endpoint principal.

Cómo se soluciona:

  1. Valida la firma HMAC al inicio de la función.
  2. Guarda el evento en la base de datos y responde inmediatamente 200 OK.
  3. Delega el procesamiento a una Netlify Background Function.
